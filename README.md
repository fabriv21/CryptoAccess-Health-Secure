# CryptoAccess Health Secure 3.5

**Academic desktop application for cryptographic protection of healthcare information**

CryptoAccess Health Secure is a Python desktop prototype developed for a Cryptography course at **Universidad Latinoamericana de Ciencia y Tecnología (ULACIT), Costa Rica**. It demonstrates how authenticated encryption, public-key cryptography, multifactor authentication, access controls, and audit trails can be integrated into a clinical information management interface.

**Author:** Luis Fabricio Vindas Lacayo  
**Project type:** Academic prototype, not a production healthcare system  
**Application language:** Spanish

## Features

- Patient and clinical-record management using a local SQLite database.
- AES-256-GCM encryption for sensitive data and protected documents.
- RSA-3072-OAEP key wrapping and RSA-3072-PSS signatures with SHA-384.
- Argon2id password hashing and TOTP-based MFA compatible with Authy.
- Role-based permissions for administrators, physicians, reception staff, IT technicians, and an auditor.
- Key/certificate management, including local X.509 certificates and rotation/revocation workflows.
- Tamper-evident audit records linked with SHA-384 hashes.
- Appointment calendar and protected-document workflows.
- Local TLS functionality and cryptographic self-tests.

These are features represented in the source code; they are **not** claims of an independent security assessment.

## Technology stack

Python, CustomTkinter, Tkcalendar, SQLite, `cryptography`, `argon2-cffi`, `pyotp`, `qrcode`, and Pillow. See [`requirements.txt`](requirements.txt).

## Requirements

- Windows with Python 3 and pip installed. The included `.bat` installer is for Windows.
- Internet access during initial dependency installation.
- Python with Tkinter available.

## Quick start (Windows PowerShell)

```powershell
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\python.exe main.py
```

You can alternatively run **`instalar_y_ejecutar.bat`** in Windows. If `python` is not recognized, install Python and make sure it is on PATH.

On first launch, the application creates its local directories and secrets under `data/`. **Do not commit or share this runtime data.** Follow the on-screen account setup. MFA can be enabled afterwards in **Configuración > Seguridad > Activar Authy**.

## Cryptographic tests

After installing dependencies, execute:

```powershell
.\venv\Scripts\python.exe pruebas_criptograficas.py
```

The included script exercises TOTP, certificate verification, RSA signing, AES-GCM, local TLS, protected document packaging, backup encryption, and the audit chain. **These tests write local cryptographic material and a database**, so run them in a separate disposable copy of the project if you want a clean application environment.

## Security and usage limitations

**For learning and demonstration only.** The application has not been independently audited or approved for storing real medical records. Use only synthetic patient information. Do not commit databases, MFA seeds, certificates with private keys, exported documents, backup files, or anything generated under `data/`. The software may require further hardening, legal review, penetration testing, and deployment redesign before any real-world use.

## Academic context

This project was developed as a course prototype and can be extended and reassessed in future applied-cryptography work.
